# HA Ingress Feature — Change Log

Tracks changes made across the three repositories to add Home Assistant ingress
support to the Donetick addon.

---

## donetick-hassio-addon

- **`donetick/Dockerfile`** — base image `3.15` → `3.20`; OCI labels moved here from
  `build.yaml`; added `nginx` + its runtime dirs; `COPY nginx.conf`; exposed `8099`
- **`donetick/build.yaml`** — simplified: dropped unused `armhf`/`armv7`/`i386`,
  moved labels/args out
- **`donetick/config.yaml`** — lowercased `slug` (`Donetick` → `donetick`); added
  `ingress: true`, `ingress_port: 8099`, `panel_icon`, `apparmor: false` (deleting
  `apparmor.txt` alone isn't enough — the supervisor caches the profile); added
  `single_circle_instance` and `disable_password_auth` options
- **`donetick/entrypoint.sh`** — renamed `DT_DISABLE_SIGNUP` → `DT_IS_USER_CREATION_DISABLED`
  (matches upstream); added `DT_SINGLE_CIRCLE_INSTANCE`/`DT_DISABLE_PASSWORD_AUTH`;
  starts/stops nginx alongside the backend; `mkdir -p /run/nginx` (HA base image
  mounts `/run` as tmpfs on every start, wiping image-layer dirs)
- **`donetick/nginx.conf`** — full rewrite: port 80 proxies everything to
  `donetick:2021` (no static file serving — donetick serves its own frontend via
  `go:embed`); port 8099 ingress server only accepts the supervisor IP
  (`172.30.32.2`) and uses `sub_filter` to inject `window.__INGRESS_PATH__` into
  the HTML so the frontend knows its ingress base path; SSE/streaming support via
  `proxy_buffering off`
- **`scripts/deploy.sh`, `scripts/build-dev.sh`** (new) — local build/sync/rebuild/
  start loop against the HAOS VM

## donetick (backend)

- **`.gitignore`** — excludes `frontend/dist/` (now a build artifact, generated by
  `build-dev.sh` from the `frontend` repo rather than committed)
- **`internal/user/handler.go`** — `signUp` (password-based signup) now honors
  `single_circle_instance`, joining the shared circle (ID 1, created as "Home" on
  first signup) instead of always creating a new one per user. Previously this flag
  was only checked in the OAuth2 signup path (`thirdPartyAuthCallback`), so
  password-based signup — the only auth mode this addon currently exercises —
  silently ignored it.

## frontend

- **`vite.config.mjs`** — `base: './'` for `--mode selfhosted` builds. Vite's
  default `base: '/'` made the built `index.html` reference JS/CSS/manifest with
  absolute paths, which 404 under ingress because the page loads from a dynamic
  token-prefixed URL, not domain root. Also made the PWA manifest icons and
  `navigateFallback` relative in that mode. Non-selfhosted (cloud) builds unaffected.
- **`src/Config.js`** — new `BASE_PATH` export: reads `window.__INGRESS_PATH__`
  (injected by nginx's `sub_filter`), empty string otherwise
- **Everywhere the app builds a URL at runtime, it must respect `BASE_PATH`** —
  the vite `base` fix above only covers paths baked in at build time; anything
  constructed from `window.location.origin` or a hardcoded absolute path needed
  the same fix applied by hand:
  - `src/contexts/RouterContext.jsx`, `src/MarketingApp.jsx` — router `basename`
  - `src/utils/ApiClient.js` — API base URL (`API_URL || BASE_PATH`); forced-logout
    redirect (`window.location.href`) and its pathname guard
  - `src/i18n/config.js` — i18next-http-backend `loadPath` for locale JSON files
  - `src/utils/OAuthExchangeState.js` — pathname check that backstops the
    forced-logout redirect during an in-flight OAuth exchange
  - `src/views/Authorization/LoginView.jsx`, `Authenticating.jsx` — OAuth2
    `redirect_uri` (must match exactly between the authorize call and token exchange)
  - `src/views/Chores/components/ChoreModals.jsx`, `src/views/ChoreEdit/ChoreView.jsx`
    — chore share-link (`getNFCUrl`)
  - `src/views/components/Loading.jsx` — "back to home" fallback button

  Deliberately left alone: `src/CapacitorListener.js` (native mobile deep-link
  handling via the `donetick://` scheme — not a web/ingress code path) and a few
  genuinely external/dynamic URLs (marketing CTA to app.donetick.com, `mailto:`,
  the Stripe checkout session URL returned by the API).
